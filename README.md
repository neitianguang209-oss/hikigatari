# ひきがたり

好きな曲のコード譜を、広告なしで見ながら弾き語りするための自分専用アプリ（PWA）。

- 曲名・アーティスト名で **U-FRET / ChordWiki / コード進行メモ倉庫 / リンネのコードブック / J-Total Music / 歌ネット** の6サイトをまとめて検索し、開いた曲だけを1曲ずつ取り込んで表示する(2026-10 に3サイト追加。楽器.me はサーバーが接続を受け付けず見送り)
  - **コード進行メモ倉庫**(music-chord.com、新曲が多い・約2600曲): 曲の一覧(`page-data/search`)を6時間に1回だけ読んで照合。曲データは度数のコードと鳴る時刻(YouTube の時刻)なので、端末側で `src/music/mcsheet.js` が譜面に直す。歌詞の1文字ずつの時刻(KRC)と行の頭の時刻の差(まん中の値)で合わせて、コードを歌っている文字に置く(ChordWiki の正解9曲で、ぴったり 70%・1文字以内 94%。時刻の割り振りだけだと 48%・79%)。小節線は行の長さ÷1小節
  - **リンネのコードブック**(chord-rinne.jp): 表(1マス1拍・1行2小節)から小節線つきの譜面に。おすすめのカポ(★)の形で書かれているので、端末側でカポの数だけ上げて実際に鳴る音にする
  - **J-Total Music**(music.j-total.net、Shift_JIS): 「コードの行＋歌詞の行」を貼り付けと同じ変換で `[C]歌詞` に。「C / C /」の行は小節線に。Original Key と Capo から実際に鳴る音にする
  - 3サイトとも利用規約で自動取得・外部ツールを禁止している(U-FRET などと同じく、自分専用・開いた曲だけ読む前提)
- **ギター**: 原曲の響きのまま、いちばん押さえやすいカポ位置を自動で選ぶ。押さえ方の図を歌詞の上に出す。
  - **通常**: 教本どおりの押さえ方（F・B・Bm などはバレーコードのまま）
  - **かんたん**: 押さえにくいコードだけを省略形や響きの近いコード（F→FM7、B→B7、Bm→Bm7 など）に置き換え、前後のコードへの持ちかえが少ない形を曲全体で選ぶ（`planVoicings`）。変えたところは「弾き方とカポ」に一覧で出る
  - 曲画面の上の段(キーの横)の「教本/簡単」ボタンで、その場で切り替えられる
  - **転調**: 曲の途中の転調を見つけて(譜面に {key:} があればそれを使う)、転調のところに「カポ 2 → 4 に付けかえ」の印を出し、転調後も同じ押さえ方で弾けるコード名にする(`src/music/modulation.js`)。「付けかえない」も選べる
- **ピアノ**: 原曲キーのまま表示し、コードをタップすると鍵盤図（右手の和音・左手のベース音）が出る
- **耳コピ**(まだどのサイトにも譜面が無い新曲向け): 曲の音からコード進行を聴き取って下書きを作る(`src/music/earcopy.js`、計算は端末の中だけ・無料)。打楽器を弱めた12音の強さ＋低音で、拍ごとにコードを照合し、キーを推定してビタビ法でなめらかにする。サイトに譜面が出たらホームで知らせる(`src/lib/watch.js`)
  - **1曲まるごと**: マイク(別の端末やスピーカーで流す)・パソコンで鳴っている音(Chrome/Edge の画面共有の「システム オーディオ」)・音のファイルから。曲が鳴り始めた時刻を見つけ、曲の長さ(Apple Music)が過ぎたら自動で止まる。手早く試すなら試聴30秒(曲の一部だけ。流しながら「いま歌い出した！」を1回押して、その行を選ぶと、試聴の部分にも歌詞を当てはめる)
  - **歌詞に当てはめる**(`src/music/lyricsfit.js`): 歌詞は **Kugou の KRC(1文字ずつの歌い始めの時刻つき。Edge Function の `lyrics_krc` で取得・復号)** → LRCLIB(行ごとの時刻つき)→ 無ければ UtaTen・歌ネット(時刻なし)の順に探す(`src/lib/lyrics.js`)。KRC があれば、コードが変わる時刻に歌っている文字にそのままコードを置く(`makeWordPos`。ChordWiki の正解10曲・1061か所で、ぴったり 71%・1文字以内 90%。行の時刻からの見積もりでは 34%・73%)。小節の頭より前に歌い出す文字(「何十|回の夜」)は小節線の前に出す。時刻つきなら、歌詞の各行の時刻と聴き取った小節を照らして `|[C]歌詞の[G]途中` の形にし、前奏・間奏・後奏はコードだけの行に。小節線を入れるので自動スクロールも実際の曲と同じ速さで進む。歌い出しでタップすると歌詞の位置がぴったり合い(Kugou には前奏の長さが違う版があるので、タップがいちばん確実)、あとから「−1 / −0.1 / +0.1 / +1 秒」でも直せる。時刻なしの歌詞は、聴きながら各行の歌い出しをタップして合わせる
  - **ふりがな**: UtaTen の歌詞(漢字にふりがな)から「その文字を何拍で歌うか」を数え、行の中のコードの位置の見積もりに使う(寿命=じゅみょう=3拍)
  - **耳で合わせる**: 行をタップすると、その行だけを1・0.75・0.5倍(音の高さはそのまま)で何度でも聴ける。コードは聴き取った時刻に光り、光った瞬間に歌っている文字をタップすると、そこに決まる(`place`)。小節の数は変わらないので自動スクロールはずれない
  - **歌詞を指定**: 歌詞サイトのリンク(歌ネット・UtaTen・J-Lyric・歌詞GET・プチリリ など、Edge Function の `lyrics_url`)か、歌詞そのものを貼り付け
  - 当てはめた歌詞はバックアップ(`app_backups`)には入れない(コードと小節線だけ残す)
- **キー変更**（声に合わせる）、**BPMどおりの自動スクロール**（カウントイン・クリック音・タップテンポ・フットペダル対応）
  - 小節の数え方(`src/music/sheet.js`): 小節線と小節線のあいだ＋最初の小節線より前にコードがあれば1＋最後の小節線より後ろに何かあれば1。「何十|[Fm7]回の…」のような小節線の前の歌い出しは数えない。小節線が1本だけの行は見積もりに回す(2026-10 に直した。以前は歌い出しを1小節と数えて、譜面が実際の曲より最大1.5倍長くなっていた。直したあとは ChordWiki 10曲中7曲が曲の長さと±5%)
  - 小節線の無い譜面は、行ごとの長さを「コードの数・歌詞の音数×テンポ」から見積もる（ChordWiki の小節線つき譜面 10曲・319行で当てはめ直した式。1曲ずつ外して確かめた誤差 平均0.67小節・偏り0。`src/ui/autoscroll.js` の `estimateBars`）
  - **テンポが書かれていない曲**(U-FRET など)は、原曲の試聴(30秒)からテンポを自動で測る(`detectTempo`、曲ごとに1回・`song.tempo` に覚えて同期。倍・半分は曲の長さにいちばん近いものを選ぶ)。試聴が無ければ曲の長さから見積もる。表示は「♩=106(推定)」。ChordWiki の BPM と比べて6曲すべて誤差1以内
  - 拍の時計は音の時計(オーディオの時刻)1本。クリックは0.15秒先まで正確な時刻に予約し、コードの目印・今の行・スクロールも同じ時計から出す(画面の書きかえが遅れてもずれない)。再生は行の頭(小節の頭)から始める
  - 曲の長さ（Apple Music の再生時間）が分かる曲は、譜面がちょうど曲の長さで終わるよう進む速さを補正する。ただしクリック音オンの間は、クリックとコードの切り替わりをそろえるため BPM どおり
  - **速さの微調整**: 流している間は再生バーのすぐ上に「− 速さ 100% ＋」(5%ずつ)。テンポのパネルでは 50〜150%(1%・5%きざみ、曲ごと)。BPM・曲の長さに合わせた速さにかけ算し、クリック音も同じだけ変わる。キーボード・ペダルの → ← は2%ずつ
  - **拍子**: 譜面の {time:3/4} などから。テンポのパネルで曲ごとに 2・3・4・6拍子を選べる(メトロノームの強拍・カウント・1小節の長さが変わる)。耳コピは3拍子をはっきりしたときだけ自動で見分け(ポップス18曲で4拍子の取り違え0)、結果の画面で選び直せる
  - **今の行に色を付ける**はオン/オフできる(テンポのパネル・設定。標準はオフ。再生バーの拍の点もやめた)。**タップしたところから流す**: 歌詞・コード(行の横の空いたところでも)を押すと、押したところを含む小節の頭から自動スクロールが始まる(流している間に押すと、そこへ移って続ける。押した行は少し光る)。**メトロノームを鳴らしているときだけ 4・3・2・1 と数えてから、鳴らしていないときは押したらすぐ**流れる。**コードの押さえ方は、コードを長押し**(PC は右クリックでも)。流している間、今弾いている行はいつも画面の真ん中(行の真ん中の高さを目印にする)。設定で切れる(切ると、コードを押すと押さえ方が出る)
- **曲と合わせる**(`src/ui/music.js`・`src/music/timing.js`): 上のバーの **「原曲」** ボタンで、原曲の YouTube の動画をアプリの中で流し、譜面をその再生位置に合わせて動かす。**歌詞の文字やコードを押すと、そこから曲が流れる**(曲そのものがテンポなので、メトロノームもカウントも無し)。入り切りは曲ごとに覚える
  - 動画は曲ごとに1回だけ読み込み、押すたびに読み直さない(再生位置を移すだけ)。動画そのものは YouTube のプレーヤーが流すので、YouTube 側の広告はアプリからは消せない。出にくくなるよう、個人に合わせた広告を出さない読み込み方(プライバシー強化モード。`host: youtube-nocookie.com`)にしている(2026-10〜。再生・頭出し・速さは同じに動く。広告が無くなる保証はない)。iPhone・iPad は最初の1回だけ、動画の ▶ を直接押す必要がある
  - **譜面の行・文字 ↔ 曲の時刻**: ①コード進行メモ倉庫の曲データ(行とコードの時刻が、その曲の YouTube の動画の時刻。その譜面なら押したコードが鳴る瞬間から。ほかのサイトの譜面でも、同じ曲がそこにあれば歌詞の文字で対応させて使う) ②文字ごとの時刻つき歌詞(KRC) ③行ごとの時刻つき歌詞(LRCLIB) の順。歌詞の文字の並び(最長共通部分列)で譜面の行と対応させるので、サイトごとに行の切り方が違っても合う。作った対応は端末の中に置く(IndexedDB の `kv`、`tm2:曲ID`)
  - **動画を選ぶ**: ①のときはその動画。それ以外は Edge Function `hikigatari-yt`(YouTube の検索結果から番号・題名・チャンネル・長さだけを返す。7日キャッシュ)の候補を、曲名・本人のチャンネル・原曲と同じ長さ(=同じ音源)で並べて選ぶ。下のバーの「曲」から、別の候補に替える・YouTube のリンクを貼る・速さ(1/0.75/0.5倍)・窓の大きさ
  - **歌に合わせる**(動画と時刻がずれる曲): 曲を流しながら、いま歌っている歌詞をタップすると、その場所のずれを覚える(1か所なら全体を同じだけ、何か所かあればあいだをなめらかにつなぐ。曲ごと・動画ごとに `settings.ytFix` に覚えて同期)。0.1秒ずつの「早く・遅く」もある。歌詞の時刻がどこにも無い曲は、歌い出した行をタップして覚える(自分の歌に合わせるのと同じ)
  - **歌詞の時刻(KRC)は候補から選ぶ**: 同じ曲でも音源の版ごとに時刻の違う KRC がいくつかある(「マリーゴールド」は、動画と同じ速さのものと、2.5% ゆっくりで頭 +3.5秒・終わり −2.5秒とずれていくもの)。`hikigatari-yt` の `krc_all` で候補を4つまで取り、コード進行メモ倉庫の曲データ(動画の時刻)とのずれのばらつきがいちばん小さいものを使う(`pickKrc`。譜面にするときのコードの位置も同じ候補で決める)。それでも曲の中でずれが変わるときは、行ごとに前後5行のまん中の値を見て、全体の値から0.5秒以上離れているところだけその場所の値を使う(`alignKrc`)
  - 確かめ方: YouTube の字幕(自動生成)の単語ごとの時刻は、その動画の時刻そのもの(動画のページを開いて、通信の `api/timedtext` を読む。サーバーからは取れない)。「マリーゴールド」242か所で、押した文字の時刻と字幕の差は まん中 −0.19秒・±0.3秒以内 89%・±0.5秒以内 100%(候補を選ぶ前は ±0.5秒以内 73%)。コードを置く文字は、選ぶ前 ぴったり57%・1字以内90% → 65%・97%。保存してある9曲の正解では変わらず 74%・97%
- 並びは「コード名 → 押さえ方の図 → 歌詞」。コード名と押さえる点は単色(ライトは黒・ダークは白系)。押さえ方の図は U-FRET のように簡素に(1pxの格子・まっすぐなナット・塗りの丸・細いセーハ)、コード名はふつうのサンセリフ。上のほうのフレットを押さえる形(セーハなど)は、図の下に「何フレットめか」の数字を大きく・太く書く(歌詞の上の小さい図では約12px。前は約6pxの薄い字で読みづらかった)
- **自分の歌に合わせる**(`src/music/voice.js`): アカペラで撮った動画や録音を曲に読み込むと(この端末の IndexedDB `media` に保存・同期はしない)、**歌声を聴き取って、譜面を自動で合わせる**(2026-10 に作り直し。前は、流しながら行を何度もタップして合わせていた)
  - **聴き取り**: 録音から「歌っている区間」を取り出す(10ミリ秒ごとの音の大きさ。アカペラなら歌っていない間は静か)。iPhone の動画は数百MBあるので、動画(MP4・MOV)の目次を読んで音(AAC)の部分だけを拾い集めてから読む(`aacFromMp4`。丸ごと読むとメモリが足りなくなる)。結果は手元(`kv` の `voice:曲ID`)に置き、録音ごとに1回だけ
  - **重ねる**: 原曲で歌っている区間(曲と合わせるのと同じ時刻つき歌詞から。`timing.js` の `vocalSpans`。譜面に書かれていない くり返し も入る)と、録音の歌っている区間を、時間の順を保ったまま重ねる(動的計画法。0.1秒のこま)。歌う速さ(原曲の 0.8〜1.25倍)は先に粗く探す。**間奏は好きなだけ縮めてよい**(アカペラでは待たずに歌い進める)。行の最後の音をどこまで伸ばすかは人しだいなので罰点を付けず、歌い出しがそろうことと、行と行の間隔を重く見る。録音は曲の頭からでなくてもよい(サビから・1番だけ)
  - **ずれていたら「合わせる」→ いま歌っている歌詞を1回タップ**: 「その時刻には、その行を歌っている」という条件として重ね直す(行のどこを押しても、押すのが1秒遅れてもよい。細かい位置は歌声の切れ目から決まる)。押している間は、譜面を手で動かしても録音は飛ばず、譜面はそこに止まる(曲と合わせる の「歌に合わせる」も同じ)。全体を少しだけ直すのは「早く」「遅く」(0.2秒ずつ)
  - 歌詞やコードを押すと、そこから録音が流れる(曲と合わせる と同じ)。動画は小窓(大きく・隠す)、ゆっくり再生(音程そのまま)、区間リピートも録音で使える
  - 確かめ方(`.devdata/voicerun.js`・`voicetest.js`・`fakevoice.ps1`): KRC の時刻から作った「にせの歌」(速さ ±12%・行ごとのゆれ・間奏を縮める・息つぎで切れる)10曲で、行の頭が0.5秒以内に合う割合は平均94%。1番だけ・サビからの録音も自動で合い、合わなかった曲も1回タップで合う。行ごとの時刻しか無い歌詞(LRC)は平均83%。合成音声で作った録音(本物の音)でも、59行の歌い出しを全部聴き取って全行0.3秒以内。本物の歌声では未確認
  - 原曲の歌詞の時刻が見つからない曲・伴奏つきの録音は、自動では歌い出しだけ合わせる(テンポどおり)。あとは「合わせる」で押した場所のずれぶんを動かす(間奏をはさむときは、ずれを間奏のところに割り振る)
- **このキーで原曲を聴く**(`src/ui/keyhear.js`・`src/music/keyshift.js`): キーを変えたとき、原曲がその高さでどう聞こえるかを確かめる。上のバーの「キー」のパネルから
  - **試聴30秒**(どの端末でも): Apple Music の試聴を、端末の中でそのキーに変えてから流す(30秒で約1秒。くり返し流れる)。流しながら − ＋ で変えると、その位置のまま切りかわる。「原曲」と押し比べられる(原曲側は、キーを変えた音と同じ大きさにそろえる)
  - **1曲まるごと**(パソコンの Chrome・Edge だけ): 曲と合わせる の YouTube の音を、小さい窓(`key.html`・`src/keypop.js`)がタブの音ごと取り込み(`getDisplayMedia` の `suppressLocalAudioPlayback` で元の音は消す)、AudioWorklet(`keyshift-worklet.js`)でキーを変えて流す。キーは曲の画面と窓のどちらで変えても同じ(BroadcastChannel `hikigatari-key`)。音を抜き出して保存することはしない
  - 変え方: フェーズボコーダで r=2^(半音/12) 倍に伸ばして r 倍の速さで読み直す(窓4096・重ね8、倍音の山ごとに位相をそろえる identity phase locking、左右は同じ回転)。合成音で 5つ下げ 440→330Hz(ずれ2セント以内)、和音は他の音が −100dB 以下、左右の位相差・打った音の時刻もそのまま。位相を動かすと瞬間の山が元の約1.7倍になるので、先読み6ミリ秒のリミッターで音割れを止める(そのぶん約 −2.4dB)
- 1行は折り返さずに1行で見せる（はみ出す行だけ少し縮める。コードだけの長い行は段の数をそろえて折る）
- 検索は曲名・アーティスト名をまとめて入れても、ひらがな・カタカナでもOK。同じ曲名の曲は歌ネットの人気順で並ぶ
- **アーティストから探す**: アーティスト名で検索すると、いちばん上にアーティストの候補が出る(歌ネットのアーティスト検索。かな入力も変換して探す)。押すとその人の曲一覧(歌ネットの人気順・新しい順・曲名順、U-FRET にだけある曲も)。曲を押すと、いつもの検索と同じく U-FRET・ChordWiki・歌ネットの譜面をまとめて開く(Edge Function の `artist`)
- **お気に入り**・最近ひらいた曲・曲ごとの設定（カポ/キー/テンポ/楽器）を、iPhone・iPad・PCで同期
- **Apple Music** で聴いている曲を、iPhoneの「ショートカット」からワンタップで開ける
- 曲の画面の「…」(または「曲」の設定)から、**Apple Music** のその曲へ(iPhone・iPad は `music://` で Music アプリを直接開く。自動スクロール中なら止めてから。Music アプリの再生位置は外から動かせないので、譜面とは連動しない)。曲のページ(`appleUrl`)は iTunes の曲データから一度だけ調べて覚える
- **練習の道具**: 区間リピート（行をタップ、または「サビ」などの見出しをタップで段落まるごと）、コードごとに「いつもこの押さえ方」を覚える、**チューナー**（マイクで音の高さを測る・弦ごとの見本の音。マイクを開いてから専用の音の部品を作る・音が届かなければ作り方を変えて自動でやり直す・マイクの音の大きさのメーター。YIN＋元の細かさでの仕上げで誤差1セント前後）、Apple Music で原曲を聴く
- 最近の検索語、お気に入りの絞り込み、消した曲・外したお気に入りの「元に戻す」、印刷・PDF（操作ボタンを消して譜面だけ）
- 自分で入力・貼り付けした譜面も使える（`[C]歌詞` 形式でも、コード行＋歌詞行の形式でもOK）
- オフラインでも保存済みの曲は開ける

公開先: https://neitianguang209-oss.github.io/hikigatari/

## iPhone・iPadでの使い方

1. 公開URLを **Safari** で開く → 共有ボタン → **ホーム画面に追加**
2. 最初の端末で「はじめる」を押す（この端末が自分専用の鍵になる）
3. ほかの端末は、使っている端末の **設定 → 端末と同期 →「つなぐための6桁の数字」** に出ている数字でつなぐ（数字はそこでいつでも確認・変更できる。5回続けてまちがえると15分つなげなくなる）
4. Apple Music との連携はアプリ内の **設定 → Apple Music** の手順どおり（ショートカットは Safari で開くので、Safari でも一度つないでおく）

PC・iPad のキーボードやフットペダル: スペース＝自動スクロールの開始/停止、↓ / PageDown＝次の行（止まっているときは画面送り）、↑ / PageUp＝前の行、→ ←＝スクロールの速さを2%ずつ上げ下げ。

## 構成

| 場所 | 中身 |
|---|---|
| `index.html` / `styles.css` | React 18 + htm（CDN・ビルドなし） |
| `src/music/` | コード解析・移調・キー判定（chord.js）、譜面の解析と貼り付け変換（sheet.js）、ギターの押さえ方探索・難しさ・カポ最適化・かんたんモード（guitar.js）、ピアノのボイシング（piano.js） |
| `src/ui/` | 画面（home / song / editor / settings / welcome / apple）、自動スクロール（autoscroll.js）、チューナー（tuner.js。音の高さは `src/music/pitch.js`） |
| `src/lib/store.js` | 端末内の保存（IndexedDB）と同期。クラウドが空でも端末のデータは消さない |
| `supabase/functions/hikigatari/index.ts` | Edge Function。サイト検索・譜面取り込み・端末の鍵・同期 |
| `supabase/functions/hikigatari-yt/index.ts` | Edge Function(小さい別の関数)。曲と合わせる動画を探す。本体と同じ端末の鍵で守る(`verify_jwt: false`) |
| `sw.js` | オフライン用。**更新して公開するたびに `CACHE_NAME` の番号を上げる** |
| `icons/icon.svg` | アイコンの元絵(夜の丘で、月を背にギターを弾き語りする人)。PNG は `powershell -ExecutionPolicy Bypass -File icons/render-icons.ps1` で作る(Edge で描いて縮小) |

### Supabase（プロジェクト `gzayrjlhruhvklsidraw` に相乗り）

- テーブル: `hikigatari_songs`（曲とお気に入り・設定）、`hikigatari_devices`（端末の鍵のハッシュ）、`hikigatari_pin`（つなぐための6桁の数字・まちがえた回数・ロック期限。1行だけ）、`hikigatari_pair_codes`（旧方式の使い捨てコード）、`hikigatari_sheet_cache`（取り込みキャッシュ）
- どれも RLS 有効・ポリシーなし＝公開キーでは読めない。Edge Function（service role）だけが読み書きする
- 変更があると `app_backups`（app=`hikigatari`）へ控えを送る。取り込んだ歌詞は控えに入れない（自分で入力した譜面だけ入れる）
- Edge Function の更新: Supabase の MCP / ダッシュボードから `hikigatari` を再デプロイ（`verify_jwt: false`、認証は関数内の端末キーで行う）

### 端末をすべて失くしたとき

設定 → バックアップ用キー を控えていれば、「すでに別の端末で使っている → バックアップ用キーで復元する」で戻せる。
キーも無いときは、SQLで `delete from hikigatari_devices;` を実行すると、次に開いた端末で「はじめる」からやり直せる（曲のデータは残る）。

## ローカルで動かす

```
powershell -ExecutionPolicy Bypass -File serve.ps1
```

http://localhost:5507/ を開く（localhost では Service Worker は登録しない）。
